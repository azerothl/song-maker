# Matrice de parité MCP

État du serveur stdio `packages/mcp-server` comparé aux parcours de Song Maker. Cette matrice décrit le code et les outils MCP présents dans le dépôt ; elle ne prouve pas qu’un parcours a été exercé avec un vrai client MCP ou dans l’application Windows.

Dernière revue du code : 12 octobre 2026. À mettre à jour avec le README MCP et cette matrice lors de tout changement des outils ou des parcours principaux.

## Sens des états

- **Disponible** : un outil MCP peut effectuer et retourner cette action dans son périmètre documenté.
- **Partiel** : une partie du parcours existe, mais le résultat ou le contrat diffère de l’application.
- **Interaction requise** : l’opération dépend d’une action physique ou d’une fenêtre que le serveur stdio ne peut pas piloter.
- **Absent** : aucun outil MCP ne propose actuellement l’opération.

Les outils ci-dessous sont ceux enregistrés par `packages/mcp-server/src/server.mjs`. Projets et Bibliothèque utilisent le stockage du profil actif. La génération YuE2 en batch est un flux séparé de l’application de bureau ; le serveur n’est pas un adaptateur général de l’API Tauri.

## Parcours

| Parcours Song Maker | État MCP | Outil / limite réelle |
|---|---|---|
| Vérifier le moteur et les poids YuE2 | Disponible | `runtime_status` lit les prérequis locaux ; il ne démarre pas le moteur. |
| Inventorier les ressources et réglages du profil actif | Partiel | `list_local_resources` lit le moteur, le modèle et le séparateur choisis, les consentements et la présence des ressources épinglées. Il vérifie aussi le poids ACE-Step Turbo, le serveur audio et les consentements ; pour ACE-Step Lego, il distingue le runtime Python du moteur Turbo. Les chemins absolus sont masqués. L’activation d’un moteur déjà installé est possible via `activate_generation_settings`, application fermée ; téléchargement et installation restent absents. |
| Vérifier température et VRAM NVIDIA | Disponible | `gpu_status` lit les capteurs et les seuils du runner ; matériel NVIDIA et outils de mesure requis. |
| Créer/renommer/supprimer un projet ; lister et lire les projets | Partiel | `list_projects`, `get_project`, `create_project`, `rename_project`, `update_project` et `delete_project` lisent et modifient les métadonnées du profil actif ; suppression protégée par confirmation et révision. |
| Prises et historique de projet | Partiel | `list_project_versions` expose les versions avec métadonnées ; `import_job_generation` archive une sortie YuE2 terminée comme prise importée, `rename_project_generation` la renomme, et `use_project_generation`, `use_project_separation`, `use_project_mix` et `use_project_score` sélectionnent les versions correspondantes. Il ne lit pas le son. |
| Bibliothèque et playlists utilisateur | Partiel | `list_library`, `create_playlist`, `delete_playlist`, `add_library_track`, `remove_library_track`, `add_track_to_playlist` et `remove_track_from_playlist` partagent le fichier du profil actif. La suppression d’une playlist ou le retrait d’un titre exigent `confirm=true`. |
| Générer un morceau YuE2 ou ACE-Step | Partiel | `start_song` et `start_batch` utilisent le moteur actif du profil, ou un `engineId` explicite, puis vérifient le profil, les consentements, les fichiers et les limites GPU. YuE2 utilise le serveur local avec repli CLI ; ACE-Step exige le serveur audio, le GGUF complet et les avertissements de licence applicables. Le client choisit le dossier de sortie ; la génération n’est pas conditionnée par le contenu d’un projet existant. |
| Choisir un moteur, un modèle ou un effet depuis MCP | Partiel | `activate_generation_settings` sélectionne YuE2 Q4/Q8 ou ACE-Step déjà installé et autorisé dans l’application ; l’application doit être fermée puis redémarrée. `start_song` et `start_batch` lancent YuE2 ou ACE-Step selon le profil ou `engineId`. `get_project_mix` expose les inserts DSP internes et `update_project_mix` permet de remplacer ceux d’une piste avec une révision de production. ACE-Step Lego, VST3/AU, effets vocaux à consentement et téléchargement/installation restent hors MCP. |
| Accepter la licence YuE2 | Partiel | Un opt-in d’environnement spécifique au MCP est requis. Ce consentement n’est ni partagé avec le profil de l’application, ni modifiable par outil. |
| Générer plusieurs prises par titre | Disponible dans `start_batch` | `generations` accepte 1 à 1 000 prises par titre et 10 000 prises au total. Les prises sont rendues séquentiellement, ont des seeds dérivées distinctes et des exports suffixés `Prise NN`. Le runner MCP ne crée toujours pas de projet Song Maker automatiquement. |
| Générer avec ACE-Step ou ACE-Step Lego | Partiel | ACE-Step Turbo passe par `audiocpp_server`, avec poids présents, consentements du profil, contrôle de durée et seuil VRAM de 12 Gio ; il ne bascule jamais vers le CLI. ACE-Step Lego reste absent car son sidecar de génération conditionnelle n’est pas piloté par MCP. La génération ACE-Step doit encore être validée avec le modèle et un vrai client MCP sur une machine compatible. |
| Importer un fichier batch et le prévisualiser | Partiel | `start_batch` lit un JSON depuis le workspace MCP ; `dryRun` valide et audite les directions sans créer de projet ni lancer le GPU. Le contrat n’est pas le parcours batch de l’application. |
| Générer un batch et suivre son avancement | Partiel | `start_batch` retourne un job ID ; `job_status`, `resume_job` et `cancel_job` permettent le suivi, la reprise et l’annulation. Le runner MCP reste séquentiel, une seule génération GPU à la fois, sans reprendre la file batch durable de l’application. |
| Écouter une prise pendant un batch | Interaction requise | Le serveur expose le fichier WAV et ses contrôles qualité ; l’utilisateur doit l’écouter avec un lecteur externe avant `resume_job` lorsque la validation est demandée. |
| Exporter un WAV/FLAC/MP3 de projet ou un résultat batch | Partiel | `export_project_audio` copie un WAV généré du profil actif ou le convertit en WAV/FLAC 16/24 bits ou MP3 128/192/320 kbit/s dans le workspace ; `export_project_stems` copie les stems d’une séparation sauvegardée ; `render_project_mix` rend le mix actif ou une version sauvegardée. Le batch écrit ses WAV dans son dossier de sortie. Le rendu MCP accepte les sources WAV PCM/float32 internes au projet et ne peut pas appliquer un insert VST3 master actif. |
| Importer de l’audio dans un projet | Disponible | `import_project_audio_track` importe WAV/MP3/FLAC du workspace MCP dans le mix actif ; `import_job_audio_track` ajoute une sortie terminée YuE2 ou ACE-Step d’un job au mix et `import_job_generation` l’archive comme prise dans l’historique du projet. L’import dans le mix conserve l’original et ajoute un WAV float32 stéréo 48 kHz comme clip utilisateur. |
| Séparer un audio en stems | Partiel | `export_project_stems` exporte les stems d’une séparation déjà terminée. Le serveur MCP ne lance pas encore de nouvelle séparation et ne démarre pas audio.cpp/HTDemucs pour ce parcours. |
| Ajouter ou éditer une piste, régler l’arrangement et les effets | Partiel | `import_project_audio_track` ajoute un clip audio utilisateur ; `create_project_midi_track` crée une voix MIDI vide et sa piste liée ; `add_project_midi_track` relie une voix existante ; `update_project_mix` règle niveaux, panoramique, mute/solo, cartes, repères, clips et chaînes d’effets DSP internes (limiteur, compresseur, gate, EQ, filtre, delay, reverb) avec contrôles de révision du mix et de production. `render_project_mix` rend ces effets via le moteur partagé. Le routage détaillé et le pilotage VST/AU restent absents. |
| Charger un VST3/AU | Absent | Pas d’hôte de plugin exposé par MCP. L’hôte de l’application est suivi séparément dans #326. |
| Lire et éditer les notes d’une partition MIDI | Partiel | `get_project_score` lit la partition active et retourne `scoreRevision` ; `edit_project_score` ajoute, modifie ou supprime jusqu’à 512 notes par appel, crée une nouvelle version et conserve les précédentes. Les chemins et états propriétaires VST sont masqués. |
| Générer une partition ou convertir audio-vers-MIDI | Partiel | `transcribe_audio_to_midi` exécute BasicPitch ONNX sur un fichier audio du workspace, valide le MIDI avec le moteur partagé et publie un `.mid` sans écraser de fichier. Avec `projectId` et `expectedUpdatedAt` de `get_project`, l’outil enregistre aussi le score comme partition active ; sans ces champs, l’import reste manuel. La génération autonome de partition reste absente. |
| Enregistrer un micro ou contrôler une interface audio | Interaction requise | Aucun outil d’enregistrement ; la sélection du périphérique et l’autorisation micro requièrent l’application et l’appareil de l’utilisateur. |
| Hôte DeclUI / client Akasha | Absent | L’hôte embarqué opt-in de #343 est un service distinct ; il ne constitue pas la parité du serveur MCP de génération. |

## Couverture de l’API MCP actuelle

| Outil | Entrée et résultat | Effets / garde-fous |
|---|---|---|
| `runtime_status` | Aucun argument ; état des fichiers du moteur actif dans le profil (YuE2 ou ACE-Step). | Lecture seule ; ne lance aucune génération. |
| `list_local_resources` | Aucun argument ; réglages du profil actif et état des ressources locales connues, dont le runtime ACE-Step Lego et son reçu d’installation. | Lecture seule ; masque les chemins absolus et compare les tailles aux artefacts épinglés. Ne télécharge, n’installe ni n’active une ressource, et ne démarre pas le moteur. |
| `activate_generation_settings` | `engineId` (`yue2` ou `ace_step`), `modelId` (`q4`/`q8` pour YuE2), `expectedSettingsRevision` relue depuis `list_local_resources`, `confirmAppClosed: true`. | Sélectionne uniquement une ressource installée et consentie dans les réglages de l’application. Vérifie la révision avant et après verrouillage, écrit les réglages et les relit ; l’application doit rester fermée et être redémarrée. La confirmation de fermeture vient du client et n’est pas détectable par le serveur. Aucun téléchargement, installation ou changement de licence. |
| `gpu_status` | Aucun argument ; température et VRAM du GPU NVIDIA. | Lecture seule ; ne change pas les limites du pilote ou de la carte. |
| `list_projects` | `query` facultatif ; profil actif et résumés des projets, triés par dernière modification. | Lecture seule du dossier de données Song Maker ; les paroles sont omises des résumés. |
| `get_project` | `projectId` ; fiche de projet avec style, paroles, paramètres et identifiants de prises actives. | Lecture seule ; ne modifie ni le projet ni la bibliothèque. |
| `list_project_versions` | `projectId` ; générations (état, moteur, seed, nom, score/WAV disponibles), séparations, sauvegardes de mix et scores (métadonnées), choix actifs et chemin WAV relatif. | Lecture seule du profil actif ; liens symboliques refusés, ni paroles ni octets audio lus. Le WAV doit être ouvert séparément ; aucune version n’est restaurée. |
| `use_project_generation` | `projectId`, `generationId`, `expectedUpdatedAt` relu depuis le projet ; retourne la fiche mise à jour et la nouvelle révision. | Ne sélectionne que le WAV publié d’une génération terminée dans le profil actif. Refuse une révision périmée ; active cette prise et efface la sélection de séparation et de mix, comme `use_generation` dans l’application. Ne supprime aucun artefact. |
| `rename_project_generation` | `projectId`, `generationId`, `name`, `expectedUpdatedAt` relu depuis le projet ; retourne la fiche et la nouvelle révision. | Renomme une génération valide ou efface son nom personnalisé si `name` est vide ; exige une génération présente et une révision courante. Ne modifie pas ses fichiers audio. |
| `use_project_separation` | `projectId`, `separationId`, `expectedUpdatedAt` relu depuis le projet ; retourne la fiche mise à jour, le mix associé et la nouvelle révision. | Active uniquement une séparation sauvegardée et son mix d’origine ; vérifie les documents et profils avant écriture. Refuse une révision périmée et ne lance pas de séparation. |
| `use_project_mix` | `projectId`, `mixId`, `expectedUpdatedAt` relu depuis le projet ; retourne la fiche mise à jour, le mix choisi et la nouvelle révision. | Active uniquement un mix sauvegardé valide ; synchronise la séparation associée si elle est disponible, sinon efface la séparation active. Refuse une révision périmée. Ne change pas les réglages du mix et ne produit pas de rendu. |
| `use_project_score` | `projectId`, `scoreId`, `expectedUpdatedAt` relu depuis le projet ; retourne la fiche mise à jour, la partition et la nouvelle révision. | Active uniquement une partition sauvegardée et valide. Refuse une révision périmée ; ne modifie pas les notes. |
| `get_project_mix` | `projectId`, `mixId` facultatif (mix actif par défaut) ; retourne les pistes, clips, réglages d’arrangement, paramètres de mix, `mixRevision` SHA-256, `productionRevision` et `effectsByTrack`. | Lecture seule ; liens symboliques refusés, chemins de source absolus ou hors projet masqués, chemins VST locaux et états propriétaires des plugins omis. Ne lit pas les octets audio et ne rend pas le mix. |
| `update_project_mix` | `projectId`, `expectedMixRevision` et, pour les effets, `expectedProductionRevision` lus depuis `get_project_mix` ; gain master, réglages de piste, cartes/repères, jusqu’à 1 000 `clipEdits` ou `effectsByTrack` pour remplacer la chaîne DSP d’une ou plusieurs pistes. | Les modifications d’effets doivent être séparées des autres modifications. Refuse une révision périmée, une piste inconnue, les effets non pris en charge et les paramètres non JSON ; préserve les autres champs de `mix-vN.production.json` partagé avec l’application. VST3/AU et effets vocaux à consentement exclus. Ne rend pas l’audio. |
| `add_project_midi_track` | `projectId`, `voiceId` existant dans la partition active, `expectedScoreRevision` lue depuis `get_project_score` et `expectedMixRevision` lue depuis `get_project_mix` ; retourne l’identifiant de la piste liée. | Ajoute une piste MIDI portant le même identifiant et le même nom que la voix existante ; refuse les révisions périmées. Ne crée pas de voix, de note ni d’audio. |
| `create_project_midi_track` | `projectId`, `idempotencyKey` stable, `name` facultatif, révisions facultatives seulement quand le document correspondant n’a pas encore de version active ; retourne la voix créée, la partition et le mix. | Crée la première partition ou le premier mix si nécessaire, puis crée une voix vide dans une nouvelle version et ajoute sa piste liée ; la répétition de la même clé évite les doublons. Si le mix change entre les écritures, indique que la voix reste à relier avec `add_project_midi_track`. |
| `get_project_score` | `projectId`, `scoreId` facultatif (partition active par défaut) ; retourne le document de partition avec voix et notes. | Lecture seule ; liens symboliques refusés ; document JSON plafonné à 8 Mio. Ne modifie ni ne convertit la partition. |
| `edit_project_score` | `projectId`, `expectedScoreRevision`, 1 à 512 opérations `add`, `update` ou `delete` de notes MIDI ; retourne la nouvelle version active et sa révision. | Édite uniquement les notes de la partition active et crée un nouveau fichier `score-vN`, en conservant l’ancienne version ; révision périmée, valeurs MIDI hors bornes et voix inexistantes refusées. La génération de partition reste absente. |
| `transcribe_audio_to_midi` | `sourcePath` audio dans le workspace, `outputDirectory`, `fileName` facultatif en `.mid`, et `projectId` avec `expectedUpdatedAt` de `get_project` facultatifs. Retourne les chemins, la taille, le SHA-256, les nombres de notes et pistes, le modèle ONNX, le backend et les avertissements ; indique aussi la partition active créée si le projet a été fourni. | Exécute le script BasicPitch partagé avec Python 3.10+, `basic-pitch==0.4.0` et `onnxruntime` ; source ≤ 256 Mio et MIDI ≤ 64 Mio. Vérifie le chemin dans le workspace, le format par le moteur partagé et la révision du projet. Publie sans écrasement ; si le projet change pendant le calcul, le `.mid` reste disponible et la réponse indique l’échec d’import. |
| `export_project_audio` | `projectId`, `generationId`, `outputDirectory` dans le workspace MCP ; `format` WAV/FLAC/MP3 (défaut WAV), `fileName` avec extension correspondante, `bitDepth` 16/24 pour WAV/FLAC ou `bitrateKbps` 128/192/320 pour MP3. Retourne le chemin, la taille, les métadonnées de la source et les réglages d’export. | Copie le WAV d’une génération publiée du profil actif ou le convertit avec FFmpeg ; valide la source et le fichier créé et refuse tout écrasement. Requiert FFmpeg pour conversion. Ne rend pas le mix actif. |
| `render_project_mix` | `projectId`, `outputDirectory` du workspace MCP, `mixId` facultatif (actif par défaut), `format` WAV/FLAC/MP3, nom de fichier, profondeur 16/24 bits ou débit MP3 facultatifs. Retourne le fichier, durée, fréquence, nombre de pistes/clips, chemin de rendu et réduction de crête. | Rend les clips actifs internes (WAV PCM/float32, mono/stéréo, même fréquence que le mix) avec le moteur DSP partagé et les réglages d’automation, effets intégrés, sidechain et routage. Refuse les inserts VST3 master actifs, les sources externes, fichiers modifiés, révisions concurrentes, dépassements de limites mémoire et écrasements. FFmpeg requis pour FLAC/MP3. |
| `export_project_stems` | `projectId`, `separationId`, `outputDirectory` dans le workspace MCP et `roles` facultatif (`vocals`, `drums`, `bass`, `other`, `guitar`, `piano`). Retourne les fichiers exportés, leur hash, leurs métadonnées, la famille du séparateur et les avertissements. | Copie uniquement des stems WAV d’une séparation terminée du profil actif ; vérifie les hashes et les WAV, refuse liens symboliques, rôles absents, chemins hors workspace et écrasements. N’exécute pas une séparation. |
| `import_project_audio_track` | `projectId`, `sourcePath` WAV/MP3/FLAC dans le workspace, `expectedUpdatedAt`, `expectedMixRevision` si un mix est actif, `name`, `startMs` et `muteExisting` facultatifs. Retourne la piste, le mix et sa nouvelle révision, la durée, le chemin des deux fichiers et le SHA-256. | Conserve l’original dans `user-audio/originals`, normalise la copie en WAV float32 stéréo 48 kHz dans `user-audio/normalized`, écrit la provenance et ajoute un clip utilisateur au mix actif. Refuse les chemins hors workspace, liens symboliques, révisions périmées et mix/version non pris en charge ; FFmpeg/libsoxr requis. Ne rend pas le mix. |
| `import_job_audio_track` | `jobId`, `completedIndex` (défaut 0), `projectId`, `expectedUpdatedAt`, `expectedMixRevision` si un mix est actif, `name`, `startMs` et `muteExisting` facultatifs. Retourne le job et le titre source, la piste ajoutée, le mix, les chemins, la durée, le SHA-256 et la nouvelle `mixRevision`. | Accepte seulement une sortie indexée d’un job `completed` ou `completed_with_errors`, dont le WAV est toujours dans le workspace MCP. Réutilise l’import protégé du projet, conserve l’original et normalise une copie float32 stéréo 48 kHz. Refuse les jobs en cours, index absents, chemins hors workspace et révisions périmées ; FFmpeg/libsoxr requis. Ajoute un clip au mix, pas une version dans l’historique des générations. |
| `import_job_generation` | `jobId`, `completedIndex` (défaut 0), `projectId`, `expectedUpdatedAt` courant et `name` facultatif. Retourne la prise créée, son chemin relatif, sa durée, son SHA-256 et la provenance du job. | Accepte une sortie d’un job terminé dont le WAV reste dans son dossier de sortie du workspace ; vérifie le chemin réel, le WAV et sa taille (256 Mio max), puis publie atomiquement `request.json`, `result.json` et `audio.wav` dans un nouveau dossier `generations/gen-N`. La prise apparaît dans `list_project_versions`, mais n’est pas activée automatiquement et le mix reste inchangé. |
| `create_project` | `title` (1 à 120 caractères) ; retourne le profil actif et la nouvelle fiche. | Crée les dossiers Song Maker et un `project.json` vide ; la bibliothèque de l’application récupère cette fiche depuis le disque. |
| `rename_project` | `projectId`, `title`, `expectedUpdatedAt` ; retourne la fiche actualisée. | Refuse les titres interdits et les lectures périmées ; seule la fiche projet est modifiée. |
| `update_project` | `projectId`, `expectedUpdatedAt` et champs facultatifs du formulaire (style, paroles, cot, langue, tempo, tonalité, métrique, durée, options). | Valide les valeurs selon le contrat du brouillon Song Maker, conserve les champs omis et refuse une fiche périmée. |
| `delete_project` | `projectId`, `expectedUpdatedAt`, `confirm=true`. | Supprime le dossier du projet après contrôle du profil actif, du type de dossier et de la révision ; retire ses titres de la Bibliothèque. Si ce nettoyage échoue, la réponse signale explicitement l’avertissement. |
| `list_library` | Aucun argument ; retourne les titres explicitement conservés, les playlists et la révision. | Lit `user-library.json` du profil actif ; les projets non sélectionnés ne sont pas ajoutés. |
| `create_playlist` | `title`, `expectedUpdatedAt` (nullable avant la première écriture). | Crée une playlist dans le fichier partagé avec l’application. |
| `delete_playlist` | `playlistId`, `expectedUpdatedAt`, `confirm=true`. | Retire la playlist et ses associations ; les titres restent dans la Bibliothèque. |
| `add_library_track` | `projectId`, `generationId`, `expectedUpdatedAt` (nullable pour la première écriture). | Inscrit uniquement une prise dont le WAV se trouve dans le projet du profil actif. |
| `remove_library_track` | `projectId`, `generationId`, `expectedUpdatedAt`, `confirm=true`. | Retire l’inscription de la Bibliothèque ; le projet et le WAV sont conservés. |
| `add_track_to_playlist` | `projectId`, `generationId`, `playlistId`, `expectedUpdatedAt`. | Associe un titre déjà présent dans la Bibliothèque à une playlist. |
| `remove_track_from_playlist` | `projectId`, `generationId`, `playlistId`, `expectedUpdatedAt`. | Retire l’association ; le titre reste dans la Bibliothèque. |
| `start_song` | `title` (1–120), `style` (1–4000), `lyrics` (0–4000), `outputDirectory`, durée (30–360 s, pas de 30 s), mode instrumental, seed, langue, tempo (40–220 BPM), tonalité, métrique, `creativeDirection`, et `engineId` (`yue2`/`ace_step`) facultatif ; `modelId` (`q4`/`q8`) est réservé à YuE2. Retourne un job ID et l’état initial. | Génère un WAV YuE2 ou ACE-Step dans le workspace autorisé, avec moteur actif par défaut. Vérifie les consentements et les limites GPU ; ACE-Step exige le serveur local, le poids complet et 12 Gio libres. Une erreur de validation, de licence, de prérequis ou de capacité est retournée comme erreur MCP lisible. |
| `start_batch` | `batchFile` dans le workspace, `outputDirectory` requis hors `dryRun`, `dryRun`, `reviewBeforeNext`, `requireCreativeDirection`, `engineId` (`yue2`/`ace_step`) et `modelId` (`q4`/`q8`, YuE2 seulement). Retourne un rapport d’audit en simulation ou job ID et état initial en exécution. | `dryRun` n’utilise pas le GPU. L’exécution est séquentielle, refuse les demandes de parallélisme/retry non supportées et ne remplace pas les exports existants. Le moteur choisi reste attaché au job lors des reprises. |
| `job_status` | `jobId` UUID ; état, compteurs de prises et de titres source, fichiers terminés, erreurs, dossier de sortie, avertissements, revue audio et horodatages. | Lecture seule ; ne retourne pas les paroles. Le statut se récupère par interrogation. |
| `resume_job` | `jobId` UUID ; retourne l’état du job et les compteurs après demande de reprise/validation. | Autorise la génération suivante après arrêt de sécurité ou revue qualité. L’utilisateur doit écouter le WAV avant de confirmer une revue. |
| `cancel_job` | `jobId` UUID ; retourne l’état (`cancelling` ou terminal) et si l’annulation a été demandée. | Arrête le travail en cours et conserve les sorties déjà publiées. L’achèvement peut être coopératif ; consulter `job_status`. |

Les outils de génération exposent le progrès par `job_status` et les erreurs sous forme de message texte MCP. Ils n’émettent pas d’événements de progression. Les états de batch comprennent notamment `queued`, `running`, `paused_safety`, `paused_review`, `paused_quality`, `cancelling`, `completed`, `completed_with_errors`, `failed` et `cancelled`.

## Gaps d’acceptation restant

- Les outils de projet utilisent le profil et les fichiers du format Song Maker. Ils exposent les métadonnées des versions, le renommage d’une prise, l’activation d’une génération, d’une séparation, d’un mix sauvegardé ou d’une partition, ainsi que la lecture détaillée des documents. `list_local_resources` inventorie les ressources et consentements ; `activate_generation_settings` peut modifier les réglages de l’application seulement quand elle est fermée et pour une ressource déjà installée et autorisée.
- La Bibliothèque MCP couvre ses titres choisis et playlists ; l’import d’audio, l’export de stems déjà calculés, le rendu borné du mix avec les effets DSP internes, une partie de l’édition de clips/arrangement et la transcription audio-vers-MIDI en fichier ou vers le score actif d’un projet sont exposés. Le lancement d’une nouvelle séparation, l’édition détaillée des routages/effets du mix, le pilotage de VST/AU, la génération autonome de partition et les réglages de modèles et ressources restent hors MCP.
- Les états de job sont consultés par interrogation ; il n’y a pas de flux d’événements MCP ni de reprise de la file batch de l’application.

## Vérifications Windows avec un client réel — 11 octobre 2026

- `protocol.test.mjs` connecte le SDK MCP officiel (`Client` + `StdioClientTransport`) au processus Song Maker et découvre les 40 outils. Le scénario exerce les opérations de projet, versions, mix, partition MIDI, Bibliothèque/playlists, import/export audio et rendu offline sur un profil temporaire au format de stockage de l’application ; il vérifie aussi les fichiers WAV et JSON écrits et les relit depuis le disque. Résultat : 1/1 scénario réussi. Ce scénario ne lance pas de génération GPU réelle ni de transcription BasicPitch réelle.
- Un client MCP SDK a lu le profil isolé d’une candidate Windows créée depuis l’application : `list_projects` a retrouvé ses projets et `gen-007`, `list_library` a retrouvé le profil, et `list_local_resources` a confirmé YuE2 prêt avec le binaire configuré `v0.9.1`, Q4 installé et un GPU compatible.
- Depuis ce même client, une génération instrumentale YuE2 Q4 de 30 s s’est terminée. Le WAV de 5 759 788 octets dure 29 999 ms, est en stéréo 48 kHz/16 bits, sans écrêtage ; l’artefact a ensuite été importé via `import_job_generation` dans un projet créé par MCP au format Song Maker (`gen-001`, SHA-256 `2522938a1c6250555136d91700e4e8d87242765bbcc08c8c9febbb924d150937`). `list_project_versions` retrouve cette prise dans le profil actif.
- Cette validation prouve une génération GPU et une persistance lisible par MCP dans le format de profil Song Maker. Le projet créé par MCP n’a pas encore été ouvert visuellement dans l’application. L’installation/activation globale de ressources, ACE-Step, VST/AU et les fonctions signalées comme absentes ou partielles ci-dessus restent hors de la couverture actuelle.
